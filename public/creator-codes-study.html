One discount code per creator: what other platforms do, and what Benable should do

Phyla asked today to give each of their 20 shipped-product creators their own discount code, mainly so they can track sales internally. 28 Litsea asked for the same thing in May. This page compares how 28 creator platforms handle per-creator codes, explains what a code can and cannot measure, and recommends what Benable does now, next, and later.

Patterns

What holds across the platforms, and what it means for a managed gifting service like Benable.

Software automates codes. Most managed gifting services skip them.Every brand-run influencer tool checked creates codes in Shopify for the brand. The services closest to Benable (Statusphere, Insense, Collabstr, Archive) leave codes to the brand's own tools. Agentio is the one exception found. Offering codes at all puts Benable ahead of most direct competitors. Automating them puts it level with the software tier.
One discount per campaign, one code per creatorThe brand sets the offer once: percentage, products, dates, limits. Every creator's code copies it. Upfluence calls it a tracking plan, Aspire an offer.
The name comes from the creatorName or handle plus the discount number: JANE15, {{username}}10OFF, JaneDoe_PROMO. When a name is taken the tool adds letters or digits. A spoken code has to be easy to say and spell.
Codes are made at approval, not earlierUpfluence added "generate at approval" in May 2025 because codes made when a creator was first added "often led to discount codes being leaked or simply unused, cluttering your shop."
The code travels with a link that applies itAspire, Upfluence, CreatorIQ and Modash pair each code with a link that fills it in at checkout. The code covers video and word of mouth, the link covers Stories and bios.
Leaks are the known problemCoupon extensions pick up creator codes and apply them for shoppers who never saw the post. The strong defense, single-use codes per shopper (Aspire SecureCodes), only works through a link. A code said in a video has to stay multi-use, so the usual defenses are an end date and a cap.
Shopify Collabs gives brands codes for freeAny Shopify brand can already give creators a code and a link through Collabs at no cost. So codes alone are not a reason to buy Benable. The value is having them inside a campaign Benable already runs: created at approval, delivered with the brief, checked in review, reported in the wrap-up.
Modash's manual version is our "Next"Modash has the brand type each creator's code by hand, then shows it on the creator's dashboard with the gift and a tracking link. It is included in every Modash plan.

What a code can and cannot tell Phyla

Codes are the right tool for Benable's format. They are also a partial count, and Phyla's Target launch makes the gap bigger than usual.

What a code measures well

  • Sales from video. TikTok and Reels captions do not carry clickable links. A code said out loud or shown on screen is the one piece of attribution that survives inside the video itself. Links only work in Stories and bios.
  • Which creator drove the order. One code per creator means each order points at one creator, which is what Neil wants to see.
  • A reason to buy now. Followers ask for codes. A code turns "I want this" into a first order on phyla.com.

What it misses

  • Target. Phyla is in 611 Target stores, and "now at Target" is a core message of the 20 e-commerce videos (Tony, Oct 1). Every viewer who buys in store is invisible to a Shopify code.
  • Buyers who skip the code. People who search for Phyla later, buy at full price, or forget the code are not counted.
  • Leaked codes. Coupon browser extensions and deal sites collect working codes and apply them at checkout. Those orders get credited to a creator who did not drive them.
  • Scale. 20 nano and micro creators (5K to 50K followers) on a gifted deal. Expect small numbers per creator, with a few creators driving most of the orders.

Shopify mechanics

What the automatic version would sit on, for Nisarg. All of it is Shopify's GraphQL Admin API. Items marked Verify came from secondary sources and need a check on a dev store before the build depends on them.

Create

  • One discount per campaign: discountCodeBasicCreate with the brand's percentage, appliesOncePerCustomer, combinesWith all false, optional endsAt.
  • One code per creator on it: discountRedeemCodeBulkAdd, up to 250 codes per call, as an async job. Each code keeps its own usage count (asyncUsageCount), and usage limits apply per code.
  • Switching off one creator: delete that code with discountCodeRedeemCodeBulkDelete. Deactivating the discount stops every creator's code at once.
  • Renaming: codes added in bulk can't be renamed. Delete and add the new name.
  • Name taken: Shopify rejects the duplicate, case-insensitively. Retry with the last initial, then a digit: MAYAK15, MAYA215. Verify the exact error.
  • Limits: 20 million codes per store over its lifetime, 100 to 1,000 API points per second by plan. Neither matters at 20 creators a month.

Read

  • Per order: Order.discountCodes and discountApplications. The orders/create webhook carries discount_codes. Handle cancels and refunds too.
  • Click path: customerJourneySummary gives the first and last visit with UTM tags, so a benable.com/a/ click shows up even when no code was typed.
  • Brand-side report: Shopify's "Sales by discount" lists orders and sales per code. It counts only the discounted line items, and an order with two discounts appears under both.
  • Discount link: store.com/discount/MAYA15?redirect=/products/serum applies the code and lands on the product. Some private and in-app browsers drop it.

Permission

  • Creating codes needs the write_discounts scope, which includes reading them. ShopMy's app asks for the same.
  • Optional, not required: declare it under optional scopes and request it only when a brand turns codes on. Adding it as a required scope would prompt every connected brand to re-approve the app.
  • Order reading is limited to the last 60 days without read_all_orders. Fine for a campaign window.

Guardrails for day one

  • Keep gift orders and codes apart. Never apply a creator code to the creator's own gift order, and tag gift orders, as Collabs does.
  • Watch for leaks. A sudden jump in one code's uses, far above the creator's reach, usually means a coupon site picked it up. Alert ops.
  • Check for other affiliate apps. If the brand runs Collabs, UpPromote or GoAffPro, their "code wins" rules can take or give credit for the same order.
  • Report codes and links side by side. Tools disagree on which one wins a sale. For a brand's own tracking, show both and mark orders that have both.

The code rules we propose

  • Format: the creator's first name or handle, then the discount number. Capital letters and digits only, 12 characters at most. MAYA1515% off for Maya's followers
  • Discount: Phyla decides. Most creator codes sit at 10 to 20% off. We suggest 15% on the serum.
  • One use per customer, and it does not stack with Phyla's other codes.
  • No end date at first. Videos keep getting views for weeks, and a dead code in a live video makes the creator look bad. Phyla can switch a code off any time.
  • Not a commission. The creator earns nothing per sale on this deal. If that changes, the post disclosure has to say so.

The line we add to each creator's message

"Phyla made you your own code: MAYA15 gives your followers 15% off the serum on phyla.com. Please say it or show it in your video and add it to your caption. Our team will double-check it's in your draft."

What does not change

  • The campaign brief Phyla submitted. The code lives in our message to each creator, not in the shared brief.
  • The 5 Target creators. No codes for them.
  • The brand portal and the creator app.

Next: a code field in the portal

The smallest product version. It takes the manual steps above and puts them where brands and creators already look. Benable stores the code text. It does not create the code in Shopify, so the brand's Shopify connection stays as it is.

Brand portal

  • Setup: one optional switch in the offer step, "Give each creator a discount code for their followers", with the discount (10%, 15%, 20%, other). Off by default.
  • After approval: each approved creator's row asks for a code, with our suggestion filled in ("MAYA15"). It is an amber "Add code" action, the same anatomy as "Add tracking", because the ball is in the brand's court.
  • Creators table: the code appears in the row drawer and in the order-sheet download, so the brand has one list to create in Shopify.
  • Wrap-up: a list of codes per creator, plus where to read sales in Shopify.

Creator app and admin

  • Brief: a "Your code" card with copy button, the discount, and the instruction to say it or show it and put it in the caption.
  • Draft review: the pre-check list gains "Code is in the post" for Katie's team.
  • Admin: ops can enter or fix a code for the brand, as Katie does by hand today.
  • Data: one nullable creator_code text on the creator's campaign assignment, and creator_codes_enabled plus creator_code_discount_label on the campaign.

Later: Benable creates the codes and reports sales

Worth building once a few brands use the field. This is where the mid-market tools sit today, and it is the version 28 Litsea described in May: "if followers support the creator, they should be able to go through that creator's link and buy."

How it works

  1. Permission. Benable asks for Shopify discount access only when a brand turns codes on, so no other brand sees a new prompt.
  2. At launch: Benable creates one discount for the campaign in the brand's Shopify, with the brand's percentage, one use per customer, no stacking.
  3. At each approval: Benable adds the creator's code to that discount. If the name is taken, it adds a digit.
  4. Orders: Benable reads new orders, matches their discount codes to creators, and stores order count and sales per code.
  5. One link that carries the code: the creator's existing benable.com/a/ link redirects to Shopify's discount link, which applies the code at checkout, with Benable's UTM tags on the visit.

How results show up

  • Tracker row: a quiet line once a code has orders, "3 orders with MAYA15". Nothing before that. A row never shows a zero.
  • Wrap-up: orders and sales with creator codes for the whole campaign, and the top code.
  • Only what Benable can know: orders that used a code. No estimated revenue, no "influenced" sales.
  • A first sales number in a dashboard that has none. Since v37 the tracker shows no link metrics. Sales per creator would be the first, so the threshold rules need a decision (see open questions).
